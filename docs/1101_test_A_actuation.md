# 2026-11-01 실외 테스트 A — 제어/하드웨어 특성 측정 (모델 미사용)

## 목적

"명령을 주면 로봇이 그대로 움직이나?"를 모델과 분리해서 측정한다. 3가지를 구한다.

1. **실외 트림**: 실내에서 잰 -0.051이 실외 보도에서도 직진인지
2. **명령 → 곡률 변환 (좌우 각각)**: 하드웨어 자체에 좌우 비대칭이 있는지.
   지금까지 "우회전이 약하다"는 모델 문제로만 봤는데(docs/1011.md §3), 하드웨어 쪽은
   직진 트림 말고는 잰 적이 없다.
3. **실제 속도**: `linear=0.3`일 때 실제 m/s. rpm 기반 거리 스케일(0.329 m/rev,
   커밋 `8b456d6`) 검증용.

GPS는 이 측정에 쓰지 않는다(오차 0.4~2m라 수십 cm 단위 측정 불가). **줄자 + 분필(또는
마스킹테이프) + 휴대폰 영상**이 정답 기준이다.

## 준비물

- 줄자(10m 이상), 분필 또는 마스킹테이프, 휴대폰(영상 + 스톱워치)
- 평평하고 트인 곳(주차장 등), 최소 10m × 6m. 기존 주차선 같은 직선이 있으면 기준선으로 사용
- 로봇 배터리 충분히(1011에는 방전으로 중단된 적 있음)

## 공통 실행 방법

모든 측정은 `pure_teleop_straight_test.py` 하나로 한다. 이 스크립트는 고정 angular를
3Hz로 보내기만 하고, 끝나거나 Ctrl+C로 끊으면 정지 명령을 보낸다(`finally`).
`--angular_bias`가 실제로 보내는 angular 값이다(트림 + 회전량을 합친 값).

```bash
python3 deployment/pure_teleop_straight_test.py \
  --linear 0.3 --duration <초> --angular_bias <값> --enable_angular_dither --skip_gps \
  --log_dir deployment/logs/1101
```

- ⚠ 실행하면 로봇이 바로 움직인다. 주변을 비우고, 사람이 로봇 옆에서 따라갈 것.
- **경사 보정**: 각 조건을 **반대 방향으로 한 번 더**(같은 기준선을 거꾸로) 측정해서 평균
  낸다. 보도/주차장의 옆 경사가 한쪽으로 휘게 만드는 효과가 상쇄된다.
- 매 run 시작 전 로봇을 **기준선 위에, 기준선 방향으로** 정렬한다. 시작점에 분필 표시.

## 측정 방법: 끝점 하나로 곡률 계산

로봇이 멈춘 지점을 기준선 기준 좌표로 잰다.

- `x` = 기준선을 따라 시작점에서 끝점까지 거리(m)
- `y` = 끝점에서 기준선까지의 수직 거리(m), **왼쪽이면 +, 오른쪽이면 −**

원호 위를 일정하게 움직였다면 곡률은 (호 길이와 무관하게, 반 바퀴 미만일 때)

```
κ = 2y / (x² + y²)      [1/m, 좌회전 +]
```

직진 테스트처럼 y가 x보다 훨씬 작으면 docs/1011.md의 `κ = 2y/x²`와 같다.

## A-1. 실외 트림 확인 (직진)

| run | --angular_bias | --duration | 방향 |
|---|---|---|---|
| A1-a | -0.051 | 30 | 정방향 |
| A1-b | -0.051 | 30 | 역방향 |

- 이탈이 크면(6m에 30cm 이상) 보정량을 계산해서 한 쌍 더 측정:
  `새 트림 = -0.051 - κ_평균 / 7.94` (7.94 = 실내에서 잰 명령→곡률 기울기)
- 스톱워치로 **실제 주행 시간**도 기록(루프 끊김으로 멈춰 있던 시간 제외) → 실제 속도 = x / 주행시간

## A-2. 좌우 회전 대칭성

트림을 기준(직진)으로 좌우 같은 크기만큼 더해서 보낸다. 아래 표의 `--angular_bias`는
트림 -0.051 기준이다(A-1에서 트림이 바뀌면 그 값으로 다시 계산).

| run | 회전량 δ | --angular_bias (= 트림 + δ) | --duration | 예상 반경 |
|---|---|---|---|---|
| A2-L1 | +0.05 (좌) | -0.001 | 15 | 약 2.5m |
| A2-R1 | −0.05 (우) | -0.101 | 15 | 약 2.5m |
| A2-L2 | +0.10 (좌) | +0.049 | 10 | 약 1.3m |
| A2-R2 | −0.10 (우) | -0.151 | 10 | 약 1.3m |

- 예상 반경은 실내 기울기 7.94로 외삽한 값이라 틀릴 수 있다. **로봇이 반 바퀴(180°) 넘게
  돌기 전에 끝나야** 위 공식이 맞으므로, 너무 빨리 돌면 `--duration`을 줄여서 다시.
- 각 run도 역방향(기준선 반대쪽에서 출발)으로 한 번 더.
- δ 크기는 실제 주행 명령 분포(|angular| 대부분 0.15 이하, audit 히스토그램)에 맞춰 골랐다.

### 판정

- `κ(좌, δ) / |κ(우, −δ)|`가 1에서 크게 벗어나면(예: 0.8 미만 또는 1.25 초과) **하드웨어
  비대칭**. 이 경우 지금의 `--angular_right_gain`은 모델 + 하드웨어 효과가 섞인 값이 된다.
- 기울기 `κ / δ`가 7.94와 크게 다르면 실외 조건에서 명령→곡률 변환이 달라진 것.

사람이 원격조종으로 경로를 몰고, 모델은 예측만 기록하는 테스트. `--observe_only`(이번에

```bash

  --ckpt checkpoints/omnivla_edge_rides11_odom_20m_20260910/best.pth --map_range 27 \
  --goal_lat <위도> --goal_lon <경도> --observe_only
```

⚠ 관측 전용 프로세스는 로봇을 **절대 멈추지 않는다**(Ctrl+C로 끝내도 정지 명령을 안 보냄).
