## 무슨 일이 있었나 (시간순)

1. `docs/0905.md`대로 코드 수정 완료, E: 드라이브(exFAT, 클러스터 256KB라 작은 파일 낭비 심함)에
   재생성 시도 → 디스크 공간 부족(exFAT 오버헤드 때문)으로 195/331 에피소드에서 실패.
2. E: 정리 후 D: 드라이브(NTFS, 4KB 클러스터)로 재시작 → 정상 진행.
3. 도중 노트북 배터리 방전으로 세션 중단 → 재연결 후 D: 재생성 이어서 진행.
4. **사용자가 "인도가 표현 안 되고 건물을 가로지르는 것 같다"고 지적** → 확인해보니 다수
   이미지에 **"API KEY REQUIRED / carto.com/basemaps/apikey"라는 워터마크가 지도 배경에
   찍혀 있었음** (진짜 지도가 아니라 에러 placeholder 이미지가 배경으로 들어간 것 — 그 위에
   경로선만 정상 그려지니 "건물을 가로지르는" 것처럼 보였던 것).
5. 원인 조사: `basemaps.cartocdn.com/rastertiles/voyager_nolabels/...`가 (최소 일부 좌표에
   대해) API 키 없이는 이 placeholder를 돌려줌. 재생성 작업(`bhuy8zmix`) 즉시 중단.
6. 대안으로 되돌아가려던 **`tile.openstreetmap.org`도 막혀있음 확인** — 2026년 3월
   OpenStreetMap Foundation이 공식 도입한 **TOTP 기반 스크래핑 방지 시스템**
   (`x-totp: INVALID` 헤더로 확인, 자기 웹사이트 내장 지도용으로만 작동, 우회 시도는
   정책 위반이므로 시도 안 함). 출처: [OSMF Operations 2026-03-19 minutes](https://osmfoundation.org/wiki/Operations/Minutes/2026-03-19),
   [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/).
7. 사용자에게 3가지 선택지 제시(CARTO 유료키 발급 / MapTiler 등 타 제공자 / 라벨 있는
   타일로 타협) → **CARTO 무료 API 키 발급으로 결정.**
8. 사용자에게 CARTO 가입(carto.com → Sign up → app.carto.com에서 API 키 발급) 안내함 —
   **키 발급 대기 중, 아직 안 받음.**
9. 정리 시작: 타일 캐시(`osm_pipeline/tile_cache/cartocdn_voyager_nolabels/`)와 D:의
   부분 생성 결과(`D:\osm_maps_arrow_20260905`) 삭제 명령 실행함 — **배터리 방전으로 이
   삭제가 끝까지 됐는지 다음 세션에서 반드시 재확인 필요.**

## 다음 세션이 반드시 할 일 (순서대로)

1. **디스크 정리 완료 확인**:
   - `osm_pipeline/tile_cache/cartocdn_voyager_nolabels/` 폴더가 완전히 지워졌는지 확인
     (안 지워졌으면 마저 지울 것 — 안 그러면 오염된 placeholder 타일이 캐시에서 재사용됨).
   - `D:\osm_maps_arrow_20260905` 폴더가 완전히 지워졌는지 확인.
2. **CARTO API 키를 사용자에게 받았는지 확인.** 못 받았으면 다시 요청.
3. 키를 받으면 `osm_pipeline/py/osm_map_generator.py`의 `fetch_tile()` 함수(약 100번째 줄
   근처, `url = f"https://basemaps.cartocdn.com/rastertiles/voyager_nolabels/{zoom}/{tx}/{ty}.png"`)
   URL에 `?api_key=<키>` 추가. **키를 소스에 하드코딩하지 말고** 환경변수(`CARTO_API_KEY`
   등)로 읽어오도록 구현할 것 — git에 실수로 커밋되지 않도록.
4. **먼저 타일 1~2장만 실제로 fetch해서 워터마크가 아니라 진짜 지도인지 눈으로 확인**
   (지난번처럼 상태코드/바이트수만 보고 넘어가지 말 것 — 반드시 이미지를 직접 열어볼 것.
   `curl`로 받아서 Read 도구로 확인하는 방법 사용).
5. 확인되면 538개 세그먼트 전체 재생성을 D: 드라이브(`D:\osm_maps_arrow_20260905` 또는
   새 폴더명)로 재시작. 명령 예시(키 부분만 채워서):
   ```
   python "osm_pipeline/py/osm_map_generator.py" \
     --arrow_path "E:\CAPSTONE\processed_output_rides_11\train\data-00000-of-00001.arrow" \
     --scores_path "osm_pipeline/osm_data/output_rides_11/episode_scores.json" \
     --out_root "D:\osm_maps_arrow_20260906"
   ```
6. 완료되면 **처음 몇 장뿐 아니라 무작위로 여러 장(다양한 에피소드) 몽타주를 만들어서
   워터마크 재발 여부를 반드시 재검증할 것** — 이번에 몽타주 방식(여러 세그먼트의 중간
   프레임을 grid로 합쳐서 한 번에 훑어보기)이 문제를 찾는 데 효과적이었음, 스크립트 로직은
   이 세션 대화 기록에 있음(간단히 재작성 가능: 여러 폴더에서 osm_map 파일 하나씩 읽어
   cv2.resize+grid로 합치기).
